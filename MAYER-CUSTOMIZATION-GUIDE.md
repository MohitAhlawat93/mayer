# Mayer Website Customization Guide

Use this file as the control map for the Mayer website.

Main rule: start with content/site-content.ts. Most routine changes now live there.

## 1. Images

All profile images live in public/images/profile/.

Current important files:
- gallery-04.jpg — first homepage hero image and social/SEO image
- gallery-03.jpg — second hero slide and About image
- gallery-06.jpeg — third hero slide
- about.jpeg — fourth hero slide
- hero.jpeg — gallery image
- gallery-01.jpeg — gallery image
- gallery-05.jpeg — gallery image
- gallery-02.jpg — available image asset

Easiest replacement method: replace a file with a new image using the exact same filename. No React code change is needed.

The first hero image is intentionally still gallery-04.jpg.

To change hero order, open content/site-content.ts and edit images.heroSlides.
To change the About image, edit images.about.
To change gallery order, edit images.gallery.

Recommended image sizes:
- Hero / flexible crop: 1800–2400 px on the long edge
- Portraits: 1400–2000 px on the long edge
- Use JPG, JPEG, or WebP
- Keep mobile file size reasonable
- Update each alt description when the photo changes

## 6. Private/self-managed content

There is a non-rendered placeholder in content/site-content.ts named privateServicesPlaceholder.

It is not shown on the public website and is not included in:
- SEO metadata
- structured data
- Rose knowledge
- public rate cards

I do not connect explicit paid sexual-service menus or transactional sexual-service pricing to the public UI, chatbot, SEO, structured data, or search targets.

If you independently add adult material, review Austrian law, age requirements, advertising rules, hosting/provider rules, payment-provider rules, consent/privacy requirements, and any platform policies before publishing.

## 7. WhatsApp and Telegram

Do not hard-code contact secrets or numbers into components.

Set these in Vercel:
- NEXT_PUBLIC_WHATSAPP_NUMBER
- NEXT_PUBLIC_TELEGRAM_HANDLE

For WhatsApp use digits with country code, for example 43XXXXXXXXX.
For Telegram use the handle; the code removes a leading @ automatically.

Redeploy after changing environment variables.

## 9. Canonical production URL

Set NEXT_PUBLIC_SITE_URL in Vercel to the final production domain, without a trailing slash.

This value feeds:
- canonical URL
- structured data
- sitemap
- robots
- growth configuration

## 10. Google Search Console verification

Add the final site in Google Search Console.

For HTML meta verification, put only the verification token into this Vercel variable:
- GOOGLE_SITE_VERIFICATION

Example: if Google gives a meta tag whose content value is ABC123, set GOOGLE_SITE_VERIFICATION to ABC123.

After deployment, click Verify in Search Console.

## 11. Sitemap

## 16. Growth admin dashboard

## 17. Search Console API and GA4 Data API

Google service-account variables:
- GOOGLE_SERVICE_ACCOUNT_CLIENT_EMAIL
- GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY
- GOOGLE_SEARCH_CONSOLE_SITE_URL
- GOOGLE_ANALYTICS_PROPERTY_ID

Legacy aliases supported:
- GOOGLE_SEARCH_CONSOLE_CLIENT_EMAIL
- GOOGLE_SEARCH_CONSOLE_PRIVATE_KEY

GOOGLE_ANALYTICS_PROPERTY_ID is the numeric GA4 property ID, not the G- measurement ID.

GOOGLE_SEARCH_CONSOLE_SITE_URL must exactly match the Search Console property the service account can access.

## 19. Rose knowledge manager

Private route: /rose-admin

Default tenant should be mayer.

Use it only for approved information that you are comfortable making available to the assistant.

Do not upload passwords, payment credentials, private addresses, or confidential information.

## 22. Deployment workflow

Normal workflow:
1. edit files
2. commit to main
3. Vercel automatically builds
4. wait for successful deployment
5. test desktop and mobile
6. test /robots.txt
7. test /sitemap.xml
8. inspect title/description/canonical
9. test WhatsApp and Telegram
10. re-check Search Console after Google recrawls
