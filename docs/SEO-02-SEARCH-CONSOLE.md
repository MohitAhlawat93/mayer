# SEO-02 — Google Search Console & Indexing

## Current setup status

- `NEXT_PUBLIC_SITE_URL` is configured in Vercel for the production URL.
- `GOOGLE_SITE_VERIFICATION` is configured in Vercel for Production.
- The verification value is intentionally not stored in this repository.
- After any verification-token change, redeploy production before clicking Verify in Search Console.

This project supports reusable Google Search Console verification without hard-coding a person's verification token into the repository.

## Current site

Public URL:

`https://dancerportfolio.vercel.app/`

For the Vercel subdomain, create a **URL-prefix** Search Console property using the exact URL above. Do not use a Domain property for `vercel.app`, because Domain verification requires DNS control.

## 1. Add the Search Console property

In Google Search Console:

1. Open the property selector.
2. Choose **Add property**.
3. Choose **URL prefix**.
4. Enter the exact production URL including `https://` and the final slash:
   `https://dancerportfolio.vercel.app/`
5. Continue to ownership verification.

## 2. Recommended verification method for this project

Choose **HTML tag**.

Google will provide something similar to:

`<meta name="google-site-verification" content="ABC123..." />`

Copy only the value inside `content`.

Example:

`ABC123...`

Do not paste the whole meta tag into Vercel.

## 3. Where to put the token

In Vercel:

Project → Settings → Environment Variables

Create:

- Name: `GOOGLE_SITE_VERIFICATION`
- Value: the verification value from Google
- Environment: Production

You can also add Preview if you want previews to carry the same verification tag, but Production is the important one.

After changing an environment variable, redeploy production so Next.js regenerates the page metadata.

The code that reads this setting is:

`app/layout.tsx`

Normally you should not edit that file for each clone.

## 4. Verify ownership

After the production redeploy:

1. Open the homepage.
2. View page source.
3. Search for:
   `google-site-verification`
4. Confirm the value matches Google's token.
5. Return to Search Console.
6. Click **Verify**.

Keep the Vercel environment variable after verification. Google can re-check ownership later.

## 5. Submit the sitemap

In Search Console:

Indexing → Sitemaps

Submit:

`sitemap.xml`

The complete URL is:

`https://dancerportfolio.vercel.app/sitemap.xml`

The sitemap itself is generated by:

`app/sitemap.ts`

For normal clones, do not edit this file unless you create additional public pages.

## 6. Request indexing for the homepage

Use the URL Inspection bar and inspect:

`https://dancerportfolio.vercel.app/`

Then:

1. Check **Page fetch**.
2. Check **Indexing allowed?**
3. Check **User-declared canonical**.
4. Run **Test live URL**.
5. If the live test is indexable, click **Request indexing**.

A successful request means Google accepted the URL into its indexing queue. It does not guarantee ranking or indexing.

## 7. What counts as real proof

Track these stages separately:

- **Verified** — Search Console ownership confirmed.
- **Sitemap success** — Google can fetch the sitemap.
- **Live test successful** — Google can fetch/index the current page.
- **Crawled** — URL Inspection has a last crawl date.
- **Indexed** — URL Inspection says the URL is on Google.
- **Impressions** — Performance report shows the page/query appearing in search.
- **Clicks** — Search users actually visit the site.

Do not treat "Request indexing submitted" as proof that the page is indexed.

## 8. Main controls when cloning this website

### In the repository

`content/site-content.ts`
- Person name
- Profession
- City/location
- SEO title
- SEO description
- Public content

`app/layout.tsx`
- Structural Google verification support
- Normally no person-specific changes

`app/sitemap.ts`
- Add new public pages only when the cloned site has additional real pages

`app/robots.ts`
- Add new private/admin routes if the cloned site structure changes

### In Vercel

`NEXT_PUBLIC_SITE_URL`
- Set to the new site's final production URL.

`GOOGLE_SITE_VERIFICATION`
- Set to that site's Search Console HTML-tag verification value.

Each cloned site should use its own public URL and its own Google verification value.

## 9. When moving to a custom domain

After a custom domain is connected:

1. Set `NEXT_PUBLIC_SITE_URL` to the custom domain.
2. Redeploy.
3. Create a new Search Console property for the custom domain.
4. Prefer a Domain property when you control its DNS.
5. Submit the new custom-domain sitemap.
6. Inspect and request indexing for the custom-domain homepage.
7. Keep redirects/canonicals consistent so the old Vercel URL does not compete with the new domain.
